Architecture

AI coding tools are making developers faster but creating a new risk — code gets shipped without genuine understanding. This is a PoC of a tool that sits in the developer workflow to make sure developers can explain their own changes before anyone else has to review them. The PR Review Agent is designed as a CI gate: it generates targeted questions about a git diff and only approves the PR once the answers show genuine understanding.

Scan Pipeline

PR Review Pipeline

flowchart LR A["CLI / Web UI"] --> B["Git Diff"] B --> C["questions_agent\nPydanticAI · Claude"] C -->|questions| D["Developer\nanswers live"] D -->|answers| E["verdict_agent\nPydanticAI · Claude"] E --> F["APPROVE /\nREQUEST CHANGES"]

Scan pipeline runs in two stages: a fast regex pass across all files (6 rules covering AWS keys, GitHub tokens, DB credentials, insecure SSL, and exec() calls), then a single batched Claude call per repo with prompt caching to minimise latency and API cost. Each raw match (Finding) becomes a VerifiedFinding with a real/false-positive verdict, confidence level, and suggested fix.

PR Review pipeline is a viva voce flow: the developer pastes a git diff, the questions_agent generates 2–3 targeted questions, the developer answers live, and the verdict_agent evaluates whether the answers show genuine understanding — returning APPROVE or REQUEST CHANGES with structured feedback.
